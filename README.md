# 拾页 · 个人智能收藏夹

在自己的 NAS 上保存网页，通过 Chrome 扩展确认收藏，再用目录、标签、关键词或自然语言找到它们。针对个人、仅局域网、几百条收藏设计。自动目录最多三级，手动目录可更深。React + FastAPI + SQLite，Docker Compose 单容器。

## 在 NAS 上启动

需要 Docker Engine 和 Docker Compose 插件。把整个项目复制到 NAS，可用 NAS 的容器管理工具构建，或在项目目录执行：

```sh
cp .env.example .env
mkdir -p data
# 镜像内使用 UID/GID 10001。只调整这个应用的数据目录所有权。
sudo chown 10001:10001 data
docker compose up -d --build
docker compose ps
```

如果更改 `.env` 中的 `BOOKMARK_DATA_DIR`，请先创建那个目录并让 UID 10001 可读写。默认端口 8093，可通过 `BOOKMARK_PORT` 修改。浏览器打开 `http://NAS的局域网IP:8093`，首次访问创建唯一的管理账号。不要把服务端口转发到公网。局域网 HTTP 支持账号与扩展令牌；如果已有局域网 HTTPS 反向代理，也可使用 HTTPS 地址。

运行数据放在挂载目录，重建镜像不会删除数据。服务端只运行一个 worker，避免重复执行后台任务。任务进度保存在 SQLite，重启后可继续处理。

Docker 基础镜像有 amd64 和 arm64 版本。请在实际 NAS 上构建并验证架构兼容性；本地测试不代表已在你的 NAS 上部署。

### 使用仓库镜像部署

`compose.deploy.yaml` 使用你自行构建并发布的镜像，`.env.deploy.example` 提供镜像仓库、tag、监听地址、宿主机端口和数据目录示例。本项目没有预先发布的容器镜像；请先完成下方的构建与推送，再把 `BOOKMARK_IMAGE` 改为实际镜像仓库，`BOOKMARK_DATA_DIR` 改为 NAS 上的绝对路径，并让镜像内的 UID/GID 10001 可以读写该目录：

```sh
sudo mkdir -p /volume1/docker/bookmark-app/data
sudo chown 10001:10001 /volume1/docker/bookmark-app/data
cp .env.deploy.example .env.deploy
# 修改 .env.deploy 中的 BOOKMARK_IMAGE 和 BOOKMARK_DATA_DIR。
# 如果镜像仓库需要登录，请使用该仓库的地址；以下以 GHCR 为例。
docker login ghcr.io
docker compose --env-file .env.deploy -f compose.deploy.yaml config
docker compose --env-file .env.deploy -f compose.deploy.yaml pull
docker compose --env-file .env.deploy -f compose.deploy.yaml up -d
docker compose --env-file .env.deploy -f compose.deploy.yaml ps
```

升级时修改 `.env.deploy` 中的 `BOOKMARK_TAG`，再执行 `pull` 和 `up -d`。应用数据仍保留在 `BOOKMARK_DATA_DIR` 指定的宿主机目录。

直接通过 `http://NAS_IP:8093` 访问时，`BOOKMARK_ALLOWED_ORIGINS` 保持为空。如果通过反向代理、HTTPS 域名或其他外部端口访问，请将它设置为浏览器地址栏中完整且精确的来源，例如 `https://bookmarks.example.com`；非默认端口必须保留端口，多个来源使用英文逗号分隔。该值只包含协议、主机名和端口，不包含路径。

## 构建并推送镜像

发布需要 Git、Python 3.9+、Make，以及带 Buildx 插件的 Docker。首次使用时，复制本机发布配置并填写实际仓库域名和镜像路径，再登录该仓库：

```sh
cp .env.release.example .env.release
# 修改 .env.release 中的 REGISTRY 和 IMAGE，二者必须指向同一个仓库。
make login
```

`.env.release` 和 `.release/` 中的发布记录只保存在本机，不进入 Git 或镜像构建上下文。账号密码由 `docker login` 管理，发布配置中不保存凭据。

完成代码提交后，运行一个命令即可自动生成下一版本并上传：

```sh
make release
# 直接运行 make 或 make publish 也是同一个入口。
```

默认递增补丁版本，例如 `v0.0.5 → v0.0.6`，并同时发布版本标签与 `latest`。下一版本参考该镜像的本机成功记录和远端 `latest` 的版本注解，取较新的版本作为基准；遇到已经存在的版本会继续递增，显式指定的版本已存在时则停止。不同镜像仓库的发布记录独立保存。首次发布且没有历史记录时从 `v0.0.1` 开始；接管没有版本注解的既有 `latest` 时，首次需要显式指定新版本。

```sh
make release-plan           # 只查询下一版本和目标仓库，不构建、不上传
make release BUMP=minor      # 例如 v0.0.6 → v0.1.0
make release BUMP=major      # 例如 v0.0.6 → v1.0.0
make release TAG=v1.2.3      # 显式指定更高的新版本，格式为 v主版本.次版本.补丁版本
```

发布只使用已提交的 Git 源码快照；存在尚未提交或未跟踪的代码时会停止，避免漏发新文件或夹带本地变更。数据、凭据、截图、依赖和其他被忽略的文件不会进入快照。默认构建 `linux/amd64` 和 `linux/arm64`，也可指定 `PLATFORMS=linux/amd64` 或 `PLATFORMS=linux/arm64`。

首次构建会创建并复用独立的 `bookmark-app-multiarch-serial` Buildx builder。`buildkitd.toml` 将单个仓库连接数限制为 1；各平台依次推送 `<tag>-amd64`、`<tag>-arm64`，最后合成为带版本注解的 `<tag>` 多平台镜像，并关闭 provenance 附加清单。远端架构和版本校验通过后，才让 `latest` 指向同一份镜像；两者摘要一致后再原子写入成功记录。本机同时只能运行一个发布任务。

构建或镜像验证失败不会写入成功记录。版本镜像已上传、但更新 `latest` 失败时，已有版本镜像会保留；下次发布会跳过已占用的版本。发布命令不会自动修改 NAS 的运行容器。

### 页面版本与更新检查

管理版左侧栏顶部「拾页」右侧显示当前运行版本：正常为米金色小字，有新版本时改为琥珀金色并显示「可升级」；检查失败、尚未检查或开发版等未确认状态使用中性色。点击版本号可进入「应用设置 → 版本与更新」，查看完整版本、源码修订号、更新状态及检查时间，并提供「检查更新」。纯享版保留底部版本信息。版本号在构建时写入镜像，使用 `latest` 部署也能显示实际的 `vX.Y.Z`。直接运行源码、未指定版本的本地构建显示「开发版」。

在 `.env.release` 设置 `RELEASE_GIT_REMOTE=origin`，即可把该 remote 的公开 GitHub 仓库作为版本来源。发布流程会先验证版本镜像和 `latest`，再向这个 remote 推送指向本次源码的稳定版本标签；因此只有正式发布的版本才会进入更新检查。启用前请确认该 remote 可以接收公开的发布源码。版本号同时参考本机记录、镜像 `latest` 及公开稳定标签，避免重复使用已有版本。未配置此选项时，该发布流程构建的镜像关闭在线更新检查；手动 `docker build` 可以传入 `APP_VERSION`、`APP_REVISION`、`APP_UPDATE_REPOSITORY` 三个构建参数。

更新检查由服务端匿名读取 GitHub 的公开稳定版本标签，仅发送仓库名称，不发送书签、账号资料或镜像仓库凭据。按数字比较版本号，只接受 `v主版本.次版本.补丁版本`，不把预发布标签算作稳定版本。成功结果缓存六小时，失败缓存五分钟；手动检查可绕过缓存，但至少间隔一分钟。无法连接、无稳定标签或被限流时显示「暂时无法检查」，历史检查过期后也不会继续声称已是最新。可以设置容器环境 `CHECK_UPDATES=false`（使用部署 Compose 时设 `BOOKMARK_CHECK_UPDATES=false`）关闭联网检查。

镜像发布成功但 GitHub 标签同步失败时，命令会报「部分发布」并给出可重试的 `git push` 命令；镜像成功记录仍保留，避免下一次覆盖已有版本。页面发现更新后只提示版本，不会自动修改 NAS 容器；仍需拉取镜像并重新创建容器。

发布命令的隔离与故障测试可以单独运行：

```sh
python3 -m unittest discover -s tools/tests -v
```

## 纯享模式与管理模式

每次打开或刷新页面默认进入管理模式，可通过模式切换进入纯享模式。纯享模式使用暗紫背景和淡金库洛阵地面投影，上方是藏书册分类入口、搜索框和显式模式切换，下方是卡牌区域。藏书册打开酒红书脊与羊皮纸目录册；分类列表直接接在标题下方，父子层级、数量和选中状态可见，展开目录与选择分类分别操作，父目录包含子目录。选中分类后，标题旁显示轻量的“全部收藏”入口用于取消筛选。目录在入口下方展开，手机上使用接近全宽的浮层，高度限制在剩余屏幕空间内，长目录内部滚动；选完收起，重新打开保留展开状态。未选择目录时搜索全部正常书签，选择分类后在该目录及其子目录内搜索，输入框明确标明范围。搜索框右侧「…」提供关键词／语义搜索和刷新。模式切换保留当前分类、搜索词与搜索方式；回到纯享清除管理标签、批量选择及管理弹窗，并退出待整理、回收站等管理页面。

浏览器会记住最后一次选择的目录，刷新、重新打开或返回书签库时恢复。纯享与管理模式共用目录记忆；主动选择“全部收藏”或“清除筛选”会清除记忆。目录重命名不影响恢复，目录已删除时回到全部收藏。记忆保存在当前浏览器，按应用地址区分。

管理入口分为“全部书签”和“待整理箱”，统一使用四字名称：前者包含所有正常书签，后者是其中尚未归入目录的子集。它们不是两个互斥目录。“待整理箱”不叠加上次选择的目录筛选，也不显示目录筛选入口；归入目录后，书签会从待整理箱移出，但仍能在全部书签中找到。单条书签的状态标签仍显示“待整理”。

“待整理”按目录归属判断：只有尚未归入目录的书签才进入待整理列表，已有目录时不显示“待整理”标签，即使自动分类的内部状态尚未完成。新建书签时手动指定目录会同步记为分类完成；自动分类失败仍单独显示失败提示。插件新收藏始终先进入待整理，配置了 AI 也不会立即自动归档；可以手动指定目录，或点击“AI 整理”启动分类。待整理页面的 AI 整理只处理未归档书签，保留手动分类保护。

目录管理页可以在某一目录行点击“AI 整理”，或从顶部入口选择父目录。默认包含子目录，分别选择“整理子目录名称”“规范书签名称”和“重新分配书签目录”；归属调整默认关闭。先生成逐项前后对照，取消不需要的建议，再确认应用所选项。父目录固定，现有目录保留层级，归档和新建子目录只发生在所选范围内；手动分类和保留导入目录的书签可以单独确认改标题，但不会被自动重新分配。回收站不参与，网址、标签和笔记保留。每次最多 200 个目录、500 条书签，预览有效 30 分钟；确认前数据发生变化时要求重新生成，避免覆盖后续编辑。该入口使用设置中的分类模型、分类规则和正文发送开关，本次补充要求不会修改全局规则。

纯享与管理版目录弹层共用同一套行为：默认仅展开当前目录所在路径，其他分支折叠；未选择目录时首次打开只展示一级目录。箭头负责展开子目录，目录名称负责选择，右侧数字包含全部子目录的收藏数。“待整理”目录（含括号备注）固定显示在同级末尾，其余目录保留原有相对顺序。再次打开时保留手动展开状态，并展开当前选中目录所在的路径。两种模式都不重复展示面包屑或大号“全部收藏”按钮，仅在选中目录后于标题旁显示“返回全部收藏”，选择后关闭并将焦点返回入口；两种模式仅保留各自的外观差异。纯享各级目录名称统一16px、同一字重，数量14px；目录行最小高度44px，一级组间留白4px。宽屏每级缩进24px，窄屏20px，通过淡金分支线和组间留白区分父子层级，不使用字号差异表达层级。

魔法阵采用公开库洛阵线稿，保留中央太阳、月轮、叠方框和外围符文，通过 `tools/trace_clow_circle.py` 描摹为透明淡金 SVG 曲线路径，在大屏和高像素密度屏幕上按实际尺寸渲染，避免放大低分辨率位图；同时减弱光晕以保留清晰边缘。矢量化保留原图轮廓，不补造原图没有的细节；不是官方原画或逐帧动画复刻。来源和处理记录见 `web/public/clow-scene/provenance.json`。纯享模式在精细鼠标设备上使用封印之杖鸟头 SVG 光标，热点位于鸟喙；触屏和高对比度模式保留原生指针行为。法阵顺时针匀速旋转，90 秒一圈；圆形图案在固定地面透视内转动，卡牌和工具栏不随之旋转。页面进入后台时暂停，返回后从原角度继续；系统开启“减少动态效果”时保持静止。

纯享模式展示全部收藏或当前目录（包含子目录）的搜索结果，按竖直、平直重叠的单条牌列展示，不按手分组或分页。当前结果排名第一的书签默认居中，第二放左侧、第三放右侧，其余按左、右交替向外展开；例如八张时从左到右为 8、6、4、2、1、3、5、7。管理列表保存的顺序或搜索相关度仍作为排名依据，页面阅读与 Tab 顺序保留排名顺序。可触屏左右滑动、使用触控板横滑或在牌列内滚动鼠标滚轮；左右方向键按屏幕上的相邻位置切换，Home／End 跳到排名第一／最后的书签。切换目录、筛选后重新将第一名居中；窗口尺寸变化时保留当前浏览的中心卡牌。静止叠放按可视区域中间、左一、右一、左二、右二依次降低，左右滑动时中心随之更新。悬停只显示柔和的外围光晕，不加额外描边。

牌型按书签 ID 在 52 种库洛牌中稳定循环分配，筛选和排序不会换牌。正式页面使用 `web/public/clow-deck/` 根目录的原版 WebP 卡面（600 × 1344），保留图片内的原始汉字与人物。底部卷轴叠加实时书签标题，采用统一宋体字族、中等字重与深棕墨色，沿卷轴轻微下弯；长标题最多两行，优先词组或空格处断行并平衡行宽，换行可以替代空格包围的中点、竖线等视觉分隔符，超出部分省略，详情保留原始全文。牌列、详情翻面与快速打开的离场动画共用 `CardFace`。52 张现用卡面保持既有文件内容。

纯享顶部采用搜索为主、两侧入口为辅的对称布局：分类与管理入口为等宽144px、高44px的酒红金边按钮，中间搜索使用浅羊皮纸底、高56px并占据剩余宽度。三者共享细古金双线边框与圆角，搜索与两侧通过底色和尺寸建立主次。手机改为两行：目录与管理入口在上且平分宽度，搜索在下；沿用当前色系与原有功能。卡牌区域位置不随顶部高度调整而变化。

精绘卡面、字形、改色、去挂坠和召唤样板均为历史实验，未包含在公开源码中。生产构建仅复制当前卡面根目录文件；Git 与 Docker 构建上下文均排除本地实验、截图、设计存档和校样。

纯享牌面有两个独立入口：卡片下方的古金色「翻阅」只抽牌、按原卡比例放大翻面阅读，显示完整标题、网址、分类、摘要、笔记和标签，只有按“打开网站”才跳转；静止时显示中央卡片的翻阅入口，悬停或键盘聚焦时显示对应卡片的入口，手机左右滑动后随中央卡片更新，点击区域高44px。点击主牌面则将临时卡牌副本翻面，直接衔接 320 块不规则碎片散开淡出。完整牌背与碎片共用一次绘制的 Canvas 纹理，由同一条逐帧时间线驱动，约 0.84 秒绘制完最后一帧后先恢复原牌和牌列姿态，再新开网站标签页。原书签、数量和横向位置不变。Escape、关闭、窗口尺寸变化或切到后台会取消快速打开；若浏览器拦截新标签页，则显示详情面和明确的手动打开按钮，不自动重试。系统减少动态效果偏好下主牌面直接打开，详情取消过渡。详情使用原生模态对话框约束键盘焦点，点击空白、关闭或 Escape 会翻回原位，等待浏览器实际完成过渡后收起并将焦点还给翻阅入口；窄卡面采用紧凑布局，短横屏可滚动整张详情面。

雨之牌使用与其他牌型相同的翻牌、碎裂和打开网站流程。雨精灵召唤源码、测试与素材仅保留在本地存档，未包含在公开源码或生产包中。

切换到管理模式后，使用简洁的纵向逐条列表，直接显示标题、完整网址和目录路径。标题新开网站，复选框用于批量选择，编辑和删除可在行末直接操作；「详情」在行内展开摘要、笔记、标签和刷新内容入口，回收站条目提供恢复。手机窄屏网址自动换行，操作移到该条目下方。管理区收起大幅装饰，保留目录树、搜索、导入、分类助手、批量整理、回收站和设置；「选择当前结果」覆盖全部当前筛选结果。回到纯享模式会清除选择和管理弹窗；正在提交的请求需要完成后再切换。

管理弹框不会因点击遮罩、边框或拖选文字后在框外松开而关闭，避免编辑内容被误丢弃；使用关闭按钮、取消或 Esc 退出，保存书签时仍会阻止关闭。

目录管理每行显示正常书签数量（含全部子目录）及“本目录”直属数量，回收站记录不计入行内数字。单个删除和批量删除都会先展示直属正常书签将移入待整理箱的数量、仍留在回收站的记录数量、子目录书签保留情况及子目录提升范围；有书签时，还必须勾选“我已核对数量”才能确认删除。只删除选中的目录，书签本身保留，未选子目录中的书签保留原归属。确认期间目录或书签有变化时，整次删除会被拒绝，可以点击“重新核对数量”并再次确认。

目录管理点击「拖拽排序」进入当前页面的排序模式，每行左侧出现六点手柄，可在同级内调整顺序，子目录随父目录整体移动；点击「完成排序」退出。管理版、纯享版及新增/编辑/迁移弹框中的目录选择共用这一顺序，父目录始终在子目录前。未手动排序的同级目录按中文名称排列，旧“待整理”目录默认置底；显式拖动后以你保存的位置为准。

“全部书签”和“待整理箱”列表顶部提供「拖拽排序」，点击后直接在原列表进入排序模式，保留标题、网址和目录排版，不打开新页面或弹框。排序时连续显示当前目录范围的全部轻量书签，不受分页限制；顶部按钮保持可见，点击「完成排序」退出并恢复分页、勾选和编辑操作。按住手柄拖动、松开自动保存，靠近页面上/下边缘可自动滚动；空格拿起后也可使用上下键、Home/End 调整位置，回车放下、Esc 取消本次拖动。改变搜索、目录、标签或页面会退出排序模式。书签使用全局统一顺序，管理版及纯享版同步生效，排序不改变目录、内容、标签或备注。新收藏默认排在已保存顺序前；语义搜索仍按相关度排列，回收站保持时间排序。搜索或标签筛选期间需先清除筛选再调整顺序。JSON 备份包含手动顺序，旧备份也可继续导入。

模式作用于当前 Web 标签页，通过统一请求入口拦截纯享状态下的业务写操作。它不是新增账号权限，也不暂停已经启动的后台任务或浏览器扩展收藏。管理界面使用羊皮纸、酒红书脊与古金色的库洛典藏主题；纯享界面使用暗紫与淡金魔法阵。

书签列表通过数据库批量查询并先筛选目录、标签和关键词。管理版按每页10／20／50条从服务端读取，显示完整结果总数；全选本页后可选择当前筛选范围的全部结果，不需要下载全部正文。删除或恢复后会重新读取并补齐当前页，末页为空时自动回到有效页，失败或冲突记录继续保留选中。纯享版仍使用完整的连续牌列，两种模式都只在翻阅详情或打开编辑／刷新表单时读取完整内容。详情请求失败可重试，关闭后取消尚未完成的读取。同一次语义搜索翻页可短暂复用查询向量，修改搜索条件或主动刷新会发起新搜索；目录、记录和排名仍按当前数据库读取。

动态 API 不使用 HTTP 缓存：网页请求统一采用 `cache: "no-store"`，后端所有 `/api/` 响应（包括登录状态、列表和错误）均返回 `Cache-Control: no-store`。每次 GET/HEAD 请求还会附带不含凭据的 `_fresh` 参数，避免强制按网址缓存的反向代理重复返回旧列表；服务端忽略该参数，语义搜索的向量复用仍按 `search_id` 工作。

反向代理必须关闭 `/api/` 缓存，并清理已经保存的 API 响应。强制缓存可能绕过登录校验，把登录后的列表返回给未登录访问者；客户端的新参数不能消除已经缓存的私有数据。在 1Panel 的网站设置中检查反向代理缓存，关闭该站点代理条目的缓存并清理缓存。自定义 OpenResty/Nginx 规则需要在实际处理 `/api/` 的代理 location 中设置 `proxy_cache off;`、`proxy_cache_bypass 1;` 和 `proxy_no_cache 1;`，保留原有上游地址与转发头，再检查配置并重载。静态图片、样式和脚本可单独缓存。

目录管理支持整目录迁移书签：点击目录旁的「迁移书签」，或页面顶部的同名按钮，选择来源和目标目录。默认包含子目录中的正常书签，也可取消勾选，仅迁移来源目录直接收录的书签。预览会显示迁移数量、范围和目标，确认后统一迁入目标目录；原目录树、书签内容、标签、备注和回收站记录保留。目标目录已经收录的书签会跳过。预览后目录或书签发生变化时，本次迁移会停止，请重新预览后确认。

## 设置模型

先切换到管理模式，再进入 Web 的设置页面，分别填写分类模型和 Embedding 模型的兼容 OpenAI API 地址（例如 `https://供应商地址/v1`）、API Key 和模型名称。地址应填写 API 基础地址，不包含 `/chat/completions` 或 `/embeddings`。分类提示词可修改。密钥保存在服务端，页面只显示是否已配置，留空保留旧密钥；清除密钥需要显式操作。

未配置模型时，未指定目录的新收藏保存到待整理，关键词搜索可用。插件收藏和导入不会自动创建 AI 分类任务；网页内添加未手动分类的新书签时，仍可按已有模型配置自动分类。模型配置或提示词变化不会自动重分类已有收藏，需手动启动任务。Embedding 配置变化后需要重建语义索引；新索引完整成功后才切换，失败不会替换旧索引。关键词搜索在重建期间继续可用。

页面正文是分类依据，不是模型指令。分类会优先使用已有目录。手动设置过目录或标签的收藏受到保护，只有明确选择强制重新分类才覆盖。目录整体整理需先生成预览，由你确认后应用。

## 对话式分类助手

在“全部书签”或“待整理箱”页面点击“分类助手”。可以先勾选要整理的书签，也可以只讨论并保存分类要求。

1. 用自然语言描述目录、标签和分类偏好，与已配置的分类模型继续讨论；助手会整理出可编辑的规则草稿。
2. 检查或修改规则，点击试分类，预览所选书签中的少量样例，查看目录、标签、摘要和理由。预览不会修改书签。
3. 点击“保存规则”，让后续分类使用这份要求；保存规则不会自动重分类已有收藏。
4. 确认后点击“按此规则分类所选”，创建分类任务并在任务中心查看进度。可以选择同时保存规则，或仅用于本次任务。

手动归档的书签会被跳过；以“保留原目录”方式导入的书签继续保留原目录。对话、试分类和正式分类仅在你点击相应按钮后调用配置的模型。讨论和未保存的草稿在本次助手窗口内保留，关闭前请保存需要继续使用的规则。

## 统一品牌图标

页面内的「封印之书」资源为 `web/public/brand/sealed-book.svg` 与 `sealed-book-transparent.svg`，用于侧栏、页头、藏书册和登录页。浏览器标签页与 Chrome 扩展统一使用酒红叠页、古金星光图标，SVG 母版为 `extension/icons/bookmark.svg`，网页副本为 `web/public/favicon.svg`。

`tools/export_brand.py` 从扩展 SVG 母版生成扩展 PNG 图标，并同步网页 favicon；标签页图标更新时需要同步修改 `web/index.html` 中的图标版本参数，以刷新浏览器缓存。扩展图标的重新生成和发布需单独执行。

已加载的开发版扩展更新源码后，在 `chrome://extensions` 找到「拾页 · 智能收藏夹」并点击重新加载；若原来加载的是另一个目录的副本，应先更新该副本。无需卸载扩展，避免丢失本地配置和待同步队列。网页刷新即可获取新的 favicon 地址。

## 安装 Chrome 扩展

1. 在 Web 管理页面创建一个扩展访问令牌并复制。令牌只在创建时显示，可撤销。
2. 打开 `chrome://extensions`，启用开发者模式，点击“加载已解压的扩展程序”，选择本项目的 `extension` 目录。
3. 打开扩展“选项”，填写完整 NAS 地址和访问令牌。保存时按 Chrome 提示允许访问该服务器，然后测试连接。
4. 把扩展固定到工具栏。打开 HTTP/HTTPS 网页，点击扩展图标，在面板中核对标题和网址后点击“确认收藏”。

同步成功的新收藏进入“待整理箱”，不会因为已配置 AI 而自动归档。重复收藏已有网址会保留原目录、备注和内容，不会将已归档书签移回待整理箱。离线收藏先留在本机待同步队列，恢复连接后遵循相同规则。服务端更新后，旧版扩展也适用这条保存规则；扩展 0.1.6 更新了成功与待同步提示，加载开发版时需要重新加载扩展以更新提示。

点击工具栏图标只打开确认面板，不会直接写入收藏；点击“取消”或直接关闭面板不会产生收藏。确认后页面先保存到 Chrome 本机队列，再尝试同步到 NAS；“选项”中可查看待同步和最近同步。角标数字是待同步数量，服务器确认收到后才移出队列。同一网址重复收藏显示“已经收藏”，保留既有分类与备注。

扩展默认发送最多 12,000 字符的正文节选，可在选项中关闭；关闭后只发送网址、标题和描述。开启时正文会保存在 NAS；执行 AI 整理或建立语义索引时，会发送到相应的模型服务。页面描述仍可能包含内容信息。登录网页的完整内容不会由 NAS 自动取得，扩展可在你打开网页后提供节选。

NAS 不可达或令牌失效时，收藏留在 Chrome 本机队列；每分钟、下次启动和点击“立即同步”时重试。Chrome 扩展被卸载或清空其本地存储会丢失尚未同步的队列。切换服务器时，原待同步队列会发送到新配置的服务器，请先确认队列归属。

## 导入、搜索与批量任务

进入 Web 的“导入与导出”，上传 JSON、浏览器书签 HTML、CSV/TSV、Markdown 或纯文本网址列表，无需选择固定模板。默认保留原目录（包含空目录）；当前目录最多三层，超出部分会合并到前三层并在预览中提示。也可选择重新整理并保留来源路径。点击“分析并预览”，检查数量、目录、重复网址和无效条目，再点击确认导入；预览有效期 30 分钟，取消或更换文件不会导入书签。仅跳过文件内重复和正常书签中已有的规范化网址；回收站中的同网址不影响导入，原回收站记录保留。确认时重新检查重复项，网络失败可安全重试。单文件最多 10 MB、5000 条记录，预览仅展示前 100 条书签，确认会处理全部已识别记录。

常见格式在本地解析，不调用模型。陌生 JSON 字段或复杂文本可以显式勾选“允许模型辅助识别”，使用设置中的分类模型；文件中的样本或分段内容会发送到配置的模型服务。模型负责理解结构，返回的网址必须来自原文，遗漏或虚构网址的模型响应会被拒绝。模型有请求大小和次数限制，超过限制会提示拆分文件，避免静默截断。PDF、图片、压缩包和 Office 二进制文件尚不支持。导入不会自动启动抓取或分类；需要时选中收藏后在任务中心手动启动。

“导入与导出”按任务分为三个页签：**导入书签**提供点击或拖放单个文件、目录处理和预览确认，模型辅助与详细格式说明放在默认折叠的高级选项中；**导出书签**生成保留目录层级的有效书签 HTML；**备份与恢复**提供 JSON 下载和合并恢复，包含回收站记录和非敏感设置。页签切换保留已选文件和预览，后台处理期间禁用切换。旧版 HTML 直接导入保留在导入页底部的折叠入口。智能导入仅迁移收藏和目录，不导入账号、访问令牌或模型密钥。批量任务可暂停、继续、失败重试，默认并发两条，可在设置修改。

抓取仅支持公开 HTTP/HTTPS 页面，并限制内容大小。需要登录、已失效或拒绝抓取时，收藏仍保留，可按已有标题与网址分类，或在 Chrome 打开后通过扩展补充内容。保存重复网址不会更新旧标题和正文，需使用明确的刷新操作。

搜索支持中文关键词、目录与标签筛选，以及自然语言语义查询。语义查询需配置 Embedding 并建立索引。模型不可用时回退到关键词搜索并提示原因。普通浏览和关键词搜索不会调用模型。

删除进入回收站，30 天内可恢复，超过 30 天由服务清理。管理模式的回收站提供单条恢复、单条彻底删除、恢复所选、彻底删除所选和清空回收站。所选操作只作用于勾选记录；清空作用于整个回收站，包含当前目录、搜索或标签筛选以外的记录。永久删除前会确认范围、数量和不可恢复提示；确认后若记录变化，整次删除会被拒绝，需重新预览。永久删除会移除正文、摘要、备注和索引，历史任务解绑该记录，正常书签不受影响。正常书签与回收站的网址独立：重新收藏或导入会生成新记录，原回收站版本保留；批量恢复遇到正常书签同网址或批内重复网址时，仅恢复可恢复项，冲突项保留在回收站并保持选中。原目录已删除的书签恢复到未归档。HTML 导出适合迁移网址和目录，JSON 导出保留收藏、标签、备注、摘要、原目录及回收站记录。JSON 不包含管理账号、扩展令牌和模型密钥，不能替代完整备份。

## 备份与恢复

完整备份建议先停止容器，再复制**整个挂载数据目录**，包含 SQLite 主文件及可能存在的 WAL/SHM 文件，以及服务端密钥相关文件。不要在运行中只复制一个数据库文件。

```sh
docker compose stop
# 示例仅适用于未修改 BOOKMARK_DATA_DIR、运行目录有 data 的情况。
# 使用新的备份名称，避免覆盖已有备份。
tar -czf bookmark-backup-$(date +%Y%m%d-%H%M%S).tar.gz data
docker compose start
```

完整备份含账号凭据哈希、访问令牌哈希和模型配置，放在仅自己可读的位置。自动定时备份暂由 NAS 自带备份工具管理，备份时采用同样的停止或一致性快照方式。

恢复时停止服务，先另行备份当前数据，再把备份恢复到**新的空目录**；将 `.env` 的 `BOOKMARK_DATA_DIR` 改为恢复目录，检查 UID 10001 权限后执行 `docker compose up -d`。无需删除当前数据。恢复完整目录会恢复账号及令牌有效性；从 JSON 导入仅恢复应用数据，模型密钥需重新配置、扩展令牌需重新创建，语义索引需重建。

## 本地开发和验证

Python 3.12、Node 22。分别在项目根目录和 `web` 目录安装依赖：

```sh
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
cd web
npm ci
npm run build
cd ..
DATA_DIR=./data .venv/bin/uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

构建后服务端在 `http://127.0.0.1:8000` 提供 Web 和 API。前端热更新可另开终端在 `web` 运行 `npm run dev`，代理 `/api` 到 8000。

浏览器测试应使用隔离的 `DATA_DIR` 并自行创建测试账号。运行数据、账号、模型密钥和浏览器会话均不包含在公开源码中；`.env.example` 与 `.env.deploy.example` 仅为配置模板。

```sh
.venv/bin/python -m pytest backend/tests -q
node --test extension/tests/*.test.mjs
docker compose config
```

真实模型联网效果取决于你的 API 地址、模型和额度；自动测试使用模拟模型验证成功、失败与索引切换。实际 NAS 部署还需要确认型号/架构、局域网 IP 和持久化路径。
